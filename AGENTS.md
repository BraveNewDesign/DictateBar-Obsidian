# Agent Guide

DictateBar for Obsidian is a small TypeScript community plugin that improves the display of DictateBar Markdown entries. Read `README.md` for user-facing behavior and `CHANGELOG.md` for release history.

## Project Scope

- Keep this project focused on rendering DictateBar location boundaries, timestamps, and Markdown in Obsidian.
- The plugin does not capture dictation, modify vault files, make network requests, or manage purchases or settings.
- Preserve the Markdown source, insertion markers, entry order, and ordinary Obsidian task behavior.
- Render supported insertion marker comments as accessible visual start/end boundaries without changing their source text.
- Keep the plugin compatible with the minimum Obsidian version in `manifest.json` unless a version change is explicitly intended.
- Do not add dependencies or expand plugin capabilities without keeping the README and privacy description accurate.

## Source And Generated Files

- TypeScript implementation: `src/`.
- Styles: `styles.css`.
- Plugin metadata: `manifest.json`.
- `main.js` is the bundled plugin entry point generated by `npm run build`; keep it current when changing source.
- `dist/` contains local packaging artifacts and is ignored by Git. Do not use it as the source of truth.
- Keep `package.json` and `package-lock.json` synchronized. The package is marked private to prevent accidental npm publication; this does not prevent publishing the source repository.

## Development

Use the project-pinned dependencies and scripts:

```sh
npm ci
npm test
npm run build
```

`npm run dev` watches and rebuilds `main.js`. Focus tests on timestamp parsing and DOM rendering. Build success and unit tests do not verify behavior in Obsidian; describe runtime, Live Preview, mobile, and export checks accurately.

## Privacy And Release

- Never commit vault contents, `.obsidian/` settings, credentials, environment files, or personal machine paths.
- Keep generated archives and local outputs under ignored `dist/` unless a release explicitly calls for attaching them.
- The project uses the MIT License in `LICENSE`; preserve its notice in distributed copies.
- Keep the version in `manifest.json` aligned with `package.json` when preparing a release.
- Do not create a GitHub remote, publish a release, submit to Obsidian Community Plugins, or push changes unless explicitly requested.
